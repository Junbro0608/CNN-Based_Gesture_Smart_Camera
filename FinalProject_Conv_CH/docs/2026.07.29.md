# 2026.07.29 CNN Accelerator 작업 기록

[← 메인 README로 돌아가기](../../README.md)

## 1. 오늘 작업 결과

오늘은 `CNN.sv`를 중심으로 현재 Convolution/Pooling 가속기 구조를 정리하고
통합 검증했다.

현재 구현된 처리 범위는 다음과 같다.

```text
외부 Ping-pong Buffer
    ↓
Conv Layer 1 + ReLU + MaxPool
    ↓
Conv Layer 2 + ReLU + MaxPool
    ↓
Conv Layer 3 + ReLU + MaxPool
    ↓
독립 Pool 4
    ↓
독립 Pool 5
    ↓
CNN done
```

오늘 완료한 주요 작업은 다음과 같다.

1. `CNN.sv` 상위 FSM에서 Conv Layer 3개와 독립 Pool 2개를 순차 실행하도록
   연결했다.
2. 기본 채널 구성을 `1 → 16 → 32 → 64`로 설정했다.
3. 외부에서 Zero Padding이 완료된 데이터를 받는 구조로 확정했다.
4. 영상, Weight, Bias 및 중간 결과의 signed 연산 경로를 확인했다.
5. Weight는 signed 8-bit, Bias는 signed 32-bit로 연결했다.
6. 외부 Data Buffer와 Weight Buffer의 비동기 Read 값을 CNN 내부
   Register에 동기적으로 캡처하도록 구성했다.
7. 외부 Ping-pong Buffer는 비동기 Read, 동기 Write 방식으로 연결했다.
8. `Standalone_MaxPool`을 추가하여 Conv 없이 수행되는 Pool4와 Pool5에서
   하나의 하드웨어를 재사용하도록 했다.
9. `Feature_Buffer_Mux`를 추가하여 Conv Engine과 Standalone MaxPool 중
   하나만 외부 Ping-pong Buffer를 사용하도록 했다.
10. `CH_Result_Buffer`가 8개 CH의 4개 위치 결과를 저장한 후, 설정에 따라
    MaxPool/ReLU 처리 또는 직접 출력을 수행하도록 정리했다.
11. `tb_CNN` 통합 시뮬레이션을 현재 RTL로 다시 실행하여 골든 모델과
    비교했다.
12. `tb_CNN_Config`로 Layer 수와 출력 채널 그룹 변경을 검증했다.
13. Basys3의 `xc7a35tcpg236-1`을 대상으로 out-of-context 합성을 실행했다.

## 2. 현재 구현 범위

현재 `CNN.sv`에 포함된 범위는 다음과 같다.

| 구분 | 구현 상태 |
|---|---|
| Conv Layer 1 | 구현 및 통합 검증 완료 |
| Conv Layer 2 | 구현 및 통합 검증 완료 |
| Conv Layer 3 | 구현 및 통합 검증 완료 |
| Layer별 선택적 ReLU | 구현 및 검증 완료 |
| Layer별 선택적 2×2 MaxPool | 구현 및 검증 완료 |
| 독립 Pool4 | 구현 및 통합 검증 완료 |
| 독립 Pool5 | 구현 및 통합 검증 완료 |
| 외부 Data Ping-pong Buffer 연결 | RTL 인터페이스 및 시뮬레이션 모델 검증 |
| 외부 Weight Buffer 연결 | RTL 인터페이스 및 시뮬레이션 모델 검증 |
| Flatten | 아직 미구현 |
| FC1/FC2 | 아직 미구현 |
| 실제 Top/보드 연결 | 다른 Top 모듈과 최종 통합 필요 |
| 실제 주파수 Timing Closure | XDC 적용 후 Implementation 검증 필요 |

따라서 이 문서에서 “CNN 완료”는 **Conv 3단계와 Pool4/Pool5까지의 RTL
범위가 완료되었다**는 뜻이다. 전체 신경망의 Flatten과 FC 부분까지
완료되었다는 뜻은 아니다.

## 3. 전체 기본 구성

현재 `CNN.sv`의 기본 채널 구성은 다음과 같다.

```text
입력 채널 1
    ↓
Layer 1 출력 채널 16
    ↓
Layer 2 출력 채널 32
    ↓
Layer 3 출력 채널 64
```

물리적인 CH 연산기는 8개이므로 출력 채널은 8개 단위의 Group으로
나누어 계산한다.

| Layer | 출력 채널 | 1회 처리 채널 | Output Group 수 |
|---|---:|---:|---:|
| Layer 1 | 16 | 8 | 2 |
| Layer 2 | 32 | 8 | 4 |
| Layer 3 | 64 | 8 | 8 |

예를 들어 Layer 3은 출력 채널이 64개이므로 동일한 Conv Engine을 8번
재사용한다.

```text
Group 0: OC 0~7
Group 1: OC 8~15
...
Group 7: OC 56~63
```

## 4. CNN.sv 파라미터

`CNN.sv`의 외부 설정 파라미터는 총 **20개**다.

### 4.1 구조 및 크기 파라미터 10개

| 번호 | 파라미터 | 기본값 | 의미 |
|---:|---|---:|---|
| 1 | `NUM_CH` | 8 | 동시에 계산하는 물리 CH 개수 |
| 2 | `NUM_LAYERS` | 3 | 실행할 Conv Layer 수, 1~3 |
| 3 | `LAYER0_OUTPUT_CHANNELS` | 16 | Layer 1 출력 채널 수 |
| 4 | `LAYER1_OUTPUT_CHANNELS` | 32 | Layer 2 출력 채널 수 |
| 5 | `LAYER2_OUTPUT_CHANNELS` | 64 | Layer 3 출력 채널 수 |
| 6 | `INPUT_WIDTH` | 128 | Padding 전 논리 입력 Width |
| 7 | `INPUT_HEIGHT` | 128 | Padding 전 논리 입력 Height |
| 8 | `DATA_ADDR_WIDTH` | 32 | Feature Buffer 주소 폭 |
| 9 | `BUFFER_DATA_WIDTH` | 8 | Feature 데이터 폭 |
| 10 | `WEIGHT_ADDR_WIDTH` | 32 | Weight Buffer 주소 폭 |

활성화된 모든 Layer의 출력 채널 수는 `NUM_CH`의 배수여야 한다.

```text
LAYERn_OUTPUT_CHANNELS % NUM_CH == 0
```

### 4.2 Layer 동작 선택 파라미터 7개

| 번호 | 파라미터 | 기본값 | 의미 |
|---:|---|---:|---|
| 11 | `LAYER0_MAXPOOL_EN` | 1 | Layer 1 결과에 2×2 MaxPool 적용 |
| 12 | `LAYER1_MAXPOOL_EN` | 1 | Layer 2 결과에 2×2 MaxPool 적용 |
| 13 | `LAYER2_MAXPOOL_EN` | 1 | Layer 3 결과에 2×2 MaxPool 적용 |
| 14 | `LAYER0_RELU_EN` | 1 | Layer 1 결과에 ReLU 적용 |
| 15 | `LAYER1_RELU_EN` | 1 | Layer 2 결과에 ReLU 적용 |
| 16 | `LAYER2_RELU_EN` | 1 | Layer 3 결과에 ReLU 적용 |
| 17 | `ENABLE_STANDALONE_POOL` | 1 | Layer 3 이후 Pool4/Pool5 실행 |

### 4.3 Weight 시작 주소 파라미터 3개

| 번호 | 파라미터 | 기본값 | 의미 |
|---:|---|---:|---|
| 18 | `WEIGHT_BASE_LAYER0` | `0x1000_0000` | Layer 1 Weight 시작 주소 |
| 19 | `WEIGHT_BASE_LAYER1` | `0x1100_0000` | Layer 2 Weight 시작 주소 |
| 20 | `WEIGHT_BASE_LAYER2` | `0x1200_0000` | Layer 3 Weight 시작 주소 |

### 4.4 내부 자동 계산 값

외부 Buffer는 각 Conv Layer 입력에 1픽셀 Zero Padding을 포함한 데이터를
미리 제공한다.

기본 논리 입력이 `128×128`일 때 자동 계산되는 크기는 다음과 같다.

| 단계 | 실제 입력 | Conv 후 | 내부 MaxPool 후 |
|---|---:|---:|---:|
| Layer 1 | `1×130×130` | `16×128×128` | `16×64×64` |
| Layer 2 | `16×66×66` | `32×64×64` | `32×32×32` |
| Layer 3 | `32×34×34` | `64×32×32` | `64×16×16` |
| Pool4 | `64×16×16` | - | `64×8×8` |
| Pool5 | `64×8×8` | - | `64×4×4` |

관련 `localparam`은 다음 관계로 계산된다.

```systemverilog
LAYER1_PAD_WIDTH  = INPUT_WIDTH + 2;
LAYER1_PAD_HEIGHT = INPUT_HEIGHT + 2;

LAYER2_PAD_WIDTH  = LAYER1_OUTPUT_WIDTH + 2;
LAYER2_PAD_HEIGHT = LAYER1_OUTPUT_HEIGHT + 2;

LAYER3_PAD_WIDTH  = LAYER2_OUTPUT_WIDTH + 2;
LAYER3_PAD_HEIGHT = LAYER2_OUTPUT_HEIGHT + 2;
```

Weight 한 묶음은 출력 채널 8개에 대한 `3×3 Weight`와 32-bit Bias다.

```text
채널 하나 = Weight 9바이트 + Bias 4바이트 = 13바이트
NUM_CH=8   = 13 × 8 = 104바이트
```

따라서 기본값에서 `WEIGHT_PACKET_BYTES = 104`다.

## 5. 전체 데이터와 Bank 흐름

외부 `pingpongBuffer`는 `w_sel`로 Write Bank를 선택하고 내부에서
`r_sel = ~w_sel`로 Read Bank를 선택한다.

| 처리 단계 | Read Bank | Write Bank | 결과 크기 |
|---|---|---|---|
| Conv Layer 1 | A | B | `16×64×64` |
| Conv Layer 2 | B | A | `32×32×32` |
| Conv Layer 3 | A | B | `64×16×16` |
| Pool4 | B | A | `64×8×8` |
| Pool5 | A | B | `64×4×4` |

최종 결과는 Bank B의 주소 `0~1023`에 채널 우선 방식으로 저장된다.

```text
64 channels × 4 × 4 = 1024 values
```

Feature Map 주소는 다음 형식이다.

```text
address = channel × (width × height) + y × width + x
```

## 6. CNN 상위 FSM

`CNN.sv`의 상위 FSM은 총 8개 상태다.

```systemverilog
CNN_IDLE,
START_GROUP,
RUN_GROUP,
START_POOL4,
RUN_POOL4,
START_POOL5,
RUN_POOL5,
CNN_DONE
```

### 6.1 `CNN_IDLE`

- `start=1`을 기다린다.
- `start`가 들어오면 `layer_index=0`,
  `output_group_index=0`으로 초기화한다.
- 다음 상태는 `START_GROUP`이다.
- 이 상태에서 `busy=0`, `done=0`이다.

### 6.2 `START_GROUP`

- `Conv_Controller`에 `conv_start=1`을 한 클럭 동안 보낸다.
- 바로 다음 상태인 `RUN_GROUP`으로 이동한다.
- 시작 펄스를 한 클럭으로 제한하기 위해 별도 상태로 분리했다.

### 6.3 `RUN_GROUP`

- `Conv_Controller`의 `conv_done`을 기다린다.
- 현재 Output Group이 끝나면 다음 Group을 실행한다.
- 현재 Layer의 마지막 Group까지 끝나면 다음 Layer로 이동한다.
- 마지막 Conv Layer까지 끝나면 `START_POOL4`로 이동한다.
- `NUM_LAYERS`가 3이 아니거나 독립 Pool이 비활성화되면 바로
  `CNN_DONE`으로 이동한다.

### 6.4 `START_POOL4`

- `Standalone_MaxPool`에 `pool_start=1`을 한 클럭 동안 보낸다.
- Pool4 설정은 다음과 같다.

```text
source_bank = B
입력 = 64×16×16
출력 = 64×8×8
Write Bank = A
```

- 다음 상태는 `RUN_POOL4`다.

### 6.5 `RUN_POOL4`

- `Standalone_MaxPool`의 `pool_done`을 기다린다.
- 완료되면 `START_POOL5`로 이동한다.

### 6.6 `START_POOL5`

- 같은 `Standalone_MaxPool`에 다시 `pool_start=1`을 한 클럭 보낸다.
- Pool5 설정은 다음과 같다.

```text
source_bank = A
입력 = 64×8×8
출력 = 64×4×4
Write Bank = B
```

- 다음 상태는 `RUN_POOL5`다.

### 6.7 `RUN_POOL5`

- `pool_done`을 기다린다.
- 완료되면 `CNN_DONE`으로 이동한다.

### 6.8 `CNN_DONE`

- `done=1`이 되는 한 클럭 상태다.
- `busy=0`이다.
- 다음 클럭에 `CNN_IDLE`로 돌아간다.

전체 상태 순서는 다음과 같다.

```text
CNN_IDLE
  ↓ start
START_GROUP
  ↓ conv_start
RUN_GROUP
  ├─ 다음 Output Group → START_GROUP
  ├─ 다음 Layer        → START_GROUP
  └─ 마지막 Layer      → START_POOL4
                           ↓
                       RUN_POOL4
                           ↓ pool_done
                       START_POOL5
                           ↓
                       RUN_POOL5
                           ↓ pool_done
                       CNN_DONE
                           ↓
                       CNN_IDLE
```

## 7. Conv_Controller FSM

`Conv_Controller`는 한 Output Group에 대한 전체 영상 계산을 담당하며
총 6개 상태를 가진다.

```systemverilog
IDLE,
SET_WEIGHT_DATA,
CONV,
POST_PROCESS,
PUSH_DATA,
DONE
```

### 7.1 `IDLE`

- `CNN.sv`의 `conv_start`를 기다린다.
- Layer 설정, 입력 크기, 입력 채널 수, Bank, Weight 주소를 Register에
  저장한다.
- Shift Buffer, CH accumulator, Result Buffer를 초기화한다.

### 7.2 `SET_WEIGHT_DATA`

- 현재 입력 채널에 필요한 Weight 주소를 출력한다.
- `weight_load_start && weight_load_ready`가 성립하면 Weight 요청이
  받아들여진다.
- 외부 Weight와 Bias는 CNN 내부 `weight_reg`, `bias_reg`에 저장된다.
- 현재 2×2 출력 영역에 필요한 입력 `4×4=16개`를 주소 순서대로 읽는다.
- Data Register와 Shift Buffer의 ready 조건이 맞을 때만 다음 데이터를
  요청한다.

### 7.3 `CONV`

- Shift Buffer가 만든 4개의 3×3 Window를 CH 8개에 전달한다.
- 모든 CH가 현재 입력 채널의 Window를 처리한다.
- 입력 채널이 더 남아 있으면 다음 입력 채널의
  `SET_WEIGHT_DATA`로 돌아간다.
- 마지막 입력 채널까지 끝나면 `POST_PROCESS`로 이동한다.

### 7.4 `POST_PROCESS`

- `CH_Result_Buffer`가 CH 8개의 네 위치 결과를 모두 저장할 때까지
  기다린다.
- `result_output_valid=1`이 되면 `PUSH_DATA`로 이동한다.

### 7.5 `PUSH_DATA`

- `CH_Result_Buffer`의 결과를 한 개씩 외부 Ping-pong Buffer에 쓴다.
- `result_output_valid && result_output_ready`가 실제 출력 Handshake다.
- 마지막 결과를 쓰는 클럭에서 바로 `done`을 내지 않고 `DONE` 상태로
  이동한다.

### 7.6 `DONE`

- 마지막 동기 Write가 끝난 다음 클럭에 `done=1`을 출력한다.
- 한 클럭 후 `IDLE`로 돌아간다.

## 8. 하위 모듈 FSM

### 8.1 Shift_Buffer FSM

| 상태 | 동작 |
|---|---|
| `CAPTURE_TILE` | 16개 입력을 `4×4 tile_mem`에 저장 |
| `OUTPUT_WINDOWS` | 4개의 3×3 Window를 `00→01→10→11` 순서로 출력 |

`window_valid && window_ready`일 때만 다음 Window로 이동한다.

### 8.2 CH_Result_Buffer FSM

| 상태 | 동작 |
|---|---|
| `CAPTURE_RESULTS` | CH 8개의 위치별 결과를 `conv_mem[0:3][0:7]`에 저장 |
| `OUTPUT_RESULTS` | 설정된 Pool/ReLU 결과를 채널별로 직렬 출력 |

동작 모드는 `{MaxPool_en, Relu_en}` 두 비트로 결정된다.

| 값 | 처리 |
|---|---|
| `00` | 4개 Conv 결과를 그대로 출력 |
| `01` | 4개 Conv 결과 각각 ReLU 후 출력 |
| `10` | 4개 중 MaxPool 결과 1개 출력 |
| `11` | MaxPool 결과에 ReLU를 적용하여 1개 출력 |

### 8.3 Standalone_MaxPool FSM

| 상태 | 동작 |
|---|---|
| `IDLE` | `pool_start`와 크기/Bank 설정을 기다림 |
| `READ_PIXELS` | 한 출력에 필요한 2×2 입력 4개를 순차 비교 |
| `WRITE_RESULT` | 최댓값 하나를 반대 Bank에 동기 Write |
| `DONE` | 마지막 Write 다음 클럭에 `pool_done=1` |

## 9. CNN 외부 입출력 연결

### 9.1 CNN ACC Controller 연결

| CNN 포트 | 방향 | 연결 대상 | 의미 |
|---|---|---|---|
| `clk` | 입력 | 시스템 Clock | 모든 CNN 내부 동기 로직 Clock |
| `rst_n` | 입력 | 시스템 Reset | Active-Low Reset |
| `start` | 입력 | CNN ACC Controller | 전체 Conv/Pool 시작 펄스 |
| `busy` | 출력 | CNN ACC Controller | 전체 처리 진행 중 |
| `done` | 출력 | CNN ACC Controller | Pool5까지 완료된 한 클럭 펄스 |

`start`는 CNN이 `CNN_IDLE`일 때만 받아들인다.

### 9.2 외부 Data Ping-pong Buffer 연결

| CNN 포트 | 방향 | Ping-pong 포트 | 의미 |
|---|---|---|---|
| `rAddr` | 출력 | `rAddr` | 비동기 Read 주소 |
| `rData` | 입력 | `rData` | 현재 `rAddr`의 signed 데이터 |
| `we` | 출력 | `we` | 동기 Write Enable |
| `w_sel` | 출력 | `w_sel` | Write Bank 선택 |
| `wAddr` | 출력 | `wAddr` | Write 주소 |
| `wData` | 출력 | `wData` | signed Write 데이터 |
| `clk` | - | `rclk`, `wclk` | Top에서 CNN Clock과 연결 |

외부 Ping-pong Buffer 내부에서 `r_sel=~w_sel`이므로 Write Bank의 반대
Bank가 Read Bank가 된다.

### 9.3 외부 Weight Buffer 연결

| CNN 포트 | 방향 | 연결 대상 | 의미 |
|---|---|---|---|
| `weight_ren` | 출력 | 외부 Weight Buffer | Weight/Bias Read 요청 |
| `weight_addr` | 출력 | 외부 Weight Buffer | 현재 Output Group/입력 채널 주소 |
| `weight_data[0:7][0:8]` | 입력 | 외부 Weight Buffer | 8개 출력 채널의 3×3 Weight |
| `bias_data[0:7]` | 입력 | 외부 Weight Buffer | 8개 출력 채널의 signed 32-bit Bias |

외부 Weight Buffer의 출력은 비동기식이라고 가정한다. CNN은
`weight_ren=1`인 Clock Edge에서 모든 Weight와 Bias를 내부 Register에
캡처한다.

## 10. CNN.sv 내부 인스턴스와 신호 연결

`CNN.sv`에는 현재 다음 6개의 주요 하위 모듈이 인스턴스되어 있다.


### 10.1 U_CONV_CONTROLLER

| 방향 | Conv_Controller 신호 | 연결 |

| 출력 | `weight_load_addr` | CNN의 `controller_weight_load_addr` |

CH 하나의 결과는 다음 계산으로 만들어진다.

```text
result[oc] =
    arithmetic_shift_right(
        Σ(ic) Σ(k=0..8) pixel[ic][k] × weight[oc][ic][k]
        + bias[oc],
        OUTPUT_SHIFT
    )
```

### 10.6 U_FEATURE_BUFFER_MUX

Conv Engine과 Standalone MaxPool이 하나의 외부 Ping-pong Buffer를
공유하도록 경로를 선택한다.

```text
select_pool=0 → Conv 경로가 외부 Buffer 소유
select_pool=1 → Standalone MaxPool 경로가 외부 Buffer 소유
```

`select_pool=1`인 상태는 다음 네 상태다.

```text
START_POOL4
RUN_POOL4
START_POOL5
RUN_POOL5
```

| Mux 출력 | `select_pool=0` | `select_pool=1` |
|---|---|---|
| `buffer_rAddr` | `conv_rAddr` | `pool_rAddr` |
| `buffer_we` | `conv_we` | `pool_we` |
| `buffer_w_sel` | `conv_w_sel` | `pool_w_sel` |
| `buffer_wAddr` | `conv_wAddr` | `pool_wAddr` |
| `buffer_wData` | `conv_wData` | `pool_wData` |
| Conv으로 돌아가는 Read Data | `buffer_rData` | 0 |
| Pool로 돌아가는 Read Data | 0 | `buffer_rData` |

선택되지 않은 모듈은 `rData=0`을 받고 외부 Write 신호를 구동할 수 없다.

## 11. 내부 Register Bridge

### 11.1 Data Register Bridge

외부 Ping-pong Buffer Read는 비동기식이지만 Shift Buffer의 입력 저장은
Clock Edge에서 수행한다.

```text
Conv_Controller가 data_read_addr 출력
    ↓
Feature_Buffer_Mux가 외부 rAddr로 전달
    ↓
외부 Ping-pong Buffer가 rData를 비동기로 출력
    ↓
data_read_fire Clock Edge
    ↓
CNN 내부 data_reg에 저장
    ↓
data_reg_valid로 Shift_Buffer에 전달
```

`data_read_ready`는 다음 조건이다.

```systemverilog
data_read_ready = !data_reg_valid || shift_pixel_ready;
```

즉, Register가 비어 있거나 현재 값을 Shift Buffer가 받아가는 클럭이면
새로운 값을 받을 수 있다.

### 11.2 Weight/Bias Register Bridge

```text
Conv_Controller weight_load_start
    ↓
CNN weight_ren, weight_addr 출력
    ↓
외부 Weight Buffer의 비동기 데이터 출력
    ↓
weight_ren Clock Edge
    ↓
weight_reg[0:7][0:8], bias_reg[0:7] 저장
    ↓
weight_valid=1
    ↓
CH_wrapper가 연산에 사용
```

Weight와 Bias는 새 요청 전까지 Register에 유지되므로 동일 입력 채널의
네 Window 계산에서 재사용된다.

## 12. 전체 Handshake 정리

| 연결 | Valid/Request | Ready/Acknowledge | 전송 조건 |
|---|---|---|---|
| CNN ACC Controller → CNN | `start` | IDLE 상태 | `CNN_IDLE && start` |
| CNN → Conv_Controller | `conv_start` | Conv Controller IDLE | START_GROUP의 한 클럭 |
| Conv Controller → Weight Register | `weight_load_start` | `weight_load_ready` | 둘 다 1 |
| Conv Controller → Data Register | `data_read_enable` | `data_read_ready` | 둘 다 1 |
| Data Register → Shift Buffer | `data_reg_valid` | `shift_pixel_ready` | 둘 다 1 |
| Shift Buffer → CH Wrapper | `shift_window_valid` | `ch_pixel_ready` | 둘 다 1 |
| CH Wrapper → Result Buffer | `conv_result_valid` | `result_conv_ready` | 채널별 둘 다 1 |
| Result Buffer → Conv Controller/Buffer | `result_output_valid` | `result_output_ready` | 둘 다 1 |
| Conv Controller → CNN | `conv_done` | RUN_GROUP 상태 | 완료 감지 후 다음 Group/Layer |
| CNN → Standalone Pool | `pool_start` | Pool IDLE | START_POOL4/5의 한 클럭 |
| Standalone Pool → CNN | `pool_done` | RUN_POOL4/5 상태 | 완료 감지 후 다음 상태 |

외부 Ping-pong Buffer와 Weight Buffer는 별도 `ready`가 없는 비동기 Read
인터페이스다. CNN 내부 Register가 Clock Edge에서 값을 캡처함으로써 내부
동기 처리 경로로 변환한다.

## 13. 전체 실행 예시

`start`가 한 클럭 들어왔을 때의 흐름은 다음과 같다.

1. CNN 상위 FSM이 Layer 1, Output Group 0 설정을 만든다.
2. Conv Controller가 현재 입력 채널의 Weight/Bias를 요청한다.
3. Conv Controller가 외부 Buffer에 16개 주소를 순서대로 보낸다.
4. Data Register가 각 비동기 Read 값을 저장한다.
5. Shift Buffer가 4×4 Tile을 완성한다.
6. Shift Buffer가 3×3 Window 네 개를 `00, 01, 10, 11` 순서로 보낸다.
7. CH 8개가 현재 입력 채널에 대한 MAC 결과를 계산한다.
8. 입력 채널이 여러 개면 다음 입력 채널 Weight와 Pixel로 2~7번을
   반복하고 CH accumulator에 더한다.
9. 마지막 입력 채널에서 Bias를 더하고 8-bit 결과를 만든다.
10. CH Result Buffer가 8개 채널의 네 위치 결과를 저장한다.
11. Layer 설정에 따라 MaxPool/ReLU 처리한다.
12. 결과를 반대쪽 Ping-pong Bank에 동기 Write한다.
13. 현재 영상의 모든 Tile을 반복한다.
14. 현재 Output Group이 끝나면 다음 8개 출력 채널 Group을 실행한다.
15. Layer의 모든 Group이 끝나면 다음 Layer로 이동한다.
16. Layer 3까지 끝나면 Pool4를 실행한다.
17. Pool4 결과를 다시 읽어 Pool5를 실행한다.
18. Pool5의 마지막 Write 다음에 `CNN_DONE`으로 이동한다.
19. `done=1`을 한 클럭 출력하고 `CNN_IDLE`로 돌아간다.

### 14.3 Basys3 합성

기본 파라미터 `128×128`, `1→16→32→64`로
`xc7a35tcpg236-1` 대상 합성이 완료됐다.

| 자원 | 사용량 | Basys3 전체 | 비율 |
|---|---:|---:|---:|
| Slice LUT | 6,929 | 20,800 | 33.31% |
| Slice Register | 1,860 | 41,600 | 4.47% |
| DSP48E1 | 24 | 90 | 26.67% |
| 내부 BRAM | 0 | 50 | 0% |

CNN 내부에서 전체 Feature Map을 저장하지 않고 외부 Ping-pong Buffer를
사용하므로 현재 CNN 단독 합성에서는 내부 BRAM을 사용하지 않는다.

## 15. 검증 해석과 남은 작업

현재 확인된 결론:

- Conv/Pool RTL 데이터 경로는 골든 모델과 일치한다.
- Layer/Group FSM은 설정된 채널 수만큼 반복한다.
- Pool4는 Layer 3 결과를 읽고, Pool5는 Pool4 결과를 다시 읽는다.
- 모든 최종 Write 이후 `done`이 발생한다.
- 기본 파라미터로 Basys3 합성이 가능하다.

아직 필요한 최종 검증:

1. 실제 Top에서 외부 Ping-pong Buffer의 Clock과 포트를 연결한다.
2. 실제 Weight Buffer 주소 배치가 현재 Group/IC 주소 계산과 같은지
   확인한다.
3. XDC에 실제 Clock 주기를 지정한다.
4. Implementation 이후 Setup/Hold Timing을 확인한다.
5. 필요하면 주소 곱셈 경로에 Pipeline을 추가한다.
6. 실제 보드에서 ILA로 `start`, `busy`, `done`, `rAddr`, `wAddr`,
   `we`, `w_sel`을 확인한다.
7. 전체 네트워크에 필요한 Flatten, FC1, FC2를 별도로 구현한다.
